# Omnitunes 搜索质量与视频播放体验设计

## 目标

让按歌曲搜索时优质、匹配度高的作品优先出现；明确展示“歌曲名 + 歌手 + 发布者”；播放器在用户一次点击后尝试直接播放，并在当前媒体结束时播放队列中的下一首。视频在播放时默认可见，用户可将其隐藏而不中断声音。

## 已确认的产品决定

- 搜索结果按歌曲作品分组，优先展示与查询歌曲名、歌手匹配度最高且来源质量更高的结果。
- 结果展示固定为：主行“歌曲名 · 歌手”；次行（小字）“发布者 · 来源 · 时长”。发布者是上传者/频道，不替代歌曲歌手。
- 点击某个来源即开始该来源的播放；它不会隐式加入队列。当前媒体结束后只消费用户已经建立的队列中的下一首；队列为空则正常停止。
- 视频默认显示。点击“隐藏视频”后，仅折叠画面，嵌入播放器仍保持挂载并继续发声；点击“显示视频”恢复画面。
- 不提取或下载第三方站点音视频流；Bilibili 与 YouTube 继续使用官方嵌入播放方式。

## 搜索与数据模型

`RawHit` 增加可选的、仅供排序的质量元数据：播放量、互动量以及来源是否为官方/认证发布者。规范化流程必须将这些字段保存到 `SourceItem` 的结构化元数据中，并由搜索 API 返回给前端；现有 `publisher`、缩略图和 URL 字段保持兼容。

排序在现有歌曲名匹配和噪声惩罚之上增加以下规则：

1. 歌曲名的精确/规范化匹配仍是最强信号。
2. 查询中能匹配歌手时，歌手精确或包含匹配获得显著加分。
3. 含有“vlog、游戏、反应、歌单、合辑、教程”等非音乐语义的标题继续降权。
4. 在其余匹配结果中，官方/认证发布者、正常单曲时长、播放量和互动量作为次级质量信号；播放量使用对数尺度，避免头部视频压倒所有文本匹配。
5. 排序仅改变呈现顺序，不会过滤掉可播放结果，也不以播放量替代歌曲名/歌手匹配。

Bilibili 适配器要保留其搜索响应中的 `play` 与 `video_review`，并将“UP 主名称”同时作为发布者。歌曲名和歌手仍由现有音乐元数据解析/规范化产生；当解析不可靠时，界面使用所属 `SongWork` 的歌曲名和歌手，而不是将发布者误显示为歌手。

## 播放与队列

播放器为播放能力声明“可报告结束”与“嵌入式”两种行为：

- `stream` 与 `local` 继续由原生 `<audio>` 驱动。`ended` 事件触发后记录完成状态并调用现有队列 next API，因此可靠地自动播放队列下一首。
- `embed` 的 URL 由用户点击创建时请求自动播放，并向 iframe 授予 `autoplay`、`encrypted-media` 与 `picture-in-picture` 权限。这样可消除当前明确写死的 `autoplay=0` 所带来的第二次点击。
- 仍遵守浏览器和来源站点对未静音自动播放的限制：如果来源拒绝自动开始，播放器显示可恢复的提示与“在视频中播放”操作，而不是静默失败。
- 跨域嵌入播放器只有在提供并验证结束事件时才自动消费队列。对目前没有可靠结束事件的嵌入来源，不能用时长定时器猜测结束或错误跳歌；保留明确的“下一首”操作，并在播放状态中说明该来源无法自动衔接。

## 视频隐藏交互

播放器状态新增独立的 `videoVisible` 布尔值，默认 `true`，它不改变当前播放项、播放状态或队列。

- 嵌入视频显示时，在播放器区域提供“隐藏视频”按钮。
- 隐藏时 iframe 不卸载，只在布局中视觉折叠；底部播放器栏显示“显示视频”按钮。
- 对原生音频来源不显示视频隐藏按钮。
- 更换到新的嵌入视频时恢复为显示，避免用户误以为新选视频没有加载；同一嵌入视频的暂停、继续与隐藏/显示互不影响。

## UI 与可访问性

- 搜索结果的整张歌曲卡保持“播放最佳来源”的入口；具体来源行使用同一套“歌曲名 · 歌手 / 发布者”文字层级，并提供播放、加入队列、插入下一首操作。
- “隐藏视频”“显示视频”“下一首”使用有文字的可访问名称、键盘焦点和 tooltip；状态变化通过适当的 `aria-pressed` / live region 反馈。
- 小屏幕上视频折叠后不留下空白占位，搜索和队列区域正常回流。

## 不在本次范围内

- 不绕过第三方平台限制、不解析受保护的音频直链，也不下载媒体文件。
- 不以不可靠的倒计时模拟嵌入视频结束。
- 不改变队列的现有手动排序、去重或“插入下一首”语义。

## 验收标准

1. 搜索一首歌曲时，完全或高度匹配歌曲名与歌手、且质量信号更好的音乐结果优先于 vlog、游戏、反应、歌单等噪声视频。
2. 每个搜索来源清晰显示歌曲名、歌曲歌手和小字发布者；发布者不会替代歌手。
3. 点击 Bilibili/YouTube 等嵌入来源后，应用会以自动播放参数和 iframe 权限发起播放；来源拒绝时用户能看到可操作的说明。
4. 原生音频播放结束后，若队列中有歌曲，则自动开始队列下一首；队列为空时停止。
5. 嵌入来源没有可验证结束事件时，不会根据估算时长误跳歌，仍可手动选择下一首。
6. 播放嵌入视频时可隐藏和恢复画面，隐藏期间声音与播放状态不断开；切换到新嵌入视频时画面默认显示。
7. 后端和前端相关单元测试、TypeScript 检查、生产构建均通过。
